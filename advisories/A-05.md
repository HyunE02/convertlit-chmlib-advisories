# A-05 — CWE-129 Improper Validation of Array Index

| | |
|---|---|
| **Product** | ConvertLIT project — ConvertLIT (clit18) |
| **Affected version** | 1.8 (final release; other versions untested) |
| **Weakness** | CWE-129 |
| **CVSS 4.0** | `CVSS:4.0/AV:L/AC:L/AT:N/PR:N/UI:A/VC:N/VI:N/VA:H/SC:N/SI:N/SA:N` (6.7 MEDIUM) |

| **Routine** | `lit_reconstitute_html` |
| **CVE ID** | requested from MITRE CNA-LR on 2026-11-24 — pending |

## Description

ConvertLIT (clit18) 1.8 indexes a static pointer table with an unvalidated value in lit_reconstitute_html() in lib/litembiggen.c. The bounds check "tag < nTagRefs" guards only the else-if branch; the else branch, which is the error path taken precisely when the tag is out of range, then evaluates mapTag2Attrs[tag] with that same invalid index and dereferences the result. Because read_utf8_char() accepts the obsolete 6-byte UTF-8 encoding, tag can reach 0x7FFFFFFF, giving a read offset of table + tag*8 anywhere within roughly +/-16 GiB. The library prints "Unknown or unrecognized tag 7fffffff" immediately before the crash. The supplier has been unmaintained since 2003 and could not be contacted.

## Proof of concept

```
f10.lit (container), tag_wild_read.bin
```

## Verification

SIGSEGV at lib/litembiggen.c:338; library prints "Unknown or unrecognized tag 7fffffff" first

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open or convert untrusted .lit files with ConvertLIT. Distributions may consider dropping the package, as upstream has been unmaintained since 2003.

## Solution

No fixed version is available. The upstream project has received no update since 2003 and has no contactable maintainer.
