# A-01 — CWE-835 Loop with Unreachable Exit Condition ('Infinite Loop')

| | |
|---|---|
| **Product** | ConvertLIT project — ConvertLIT (clit18) |
| **Affected version** | 1.8 (final release; other versions untested) |
| **Weakness** | CWE-835 |
| **CVSS 4.0** | `CVSS:4.0/AV:L/AC:L/AT:N/PR:N/UI:A/VC:N/VI:N/VA:H/SC:N/SI:N/SA:N` (6.7 MEDIUM) |
| **Source file** | `lib/litheaders.c` |
| **Routine** | `lit_i_read_secondary_header` |
| **CVE ID** | requested from MITRE CNA-LR on 2026-11-24 — pending |

## Description

ConvertLIT (clit18) 1.8 contains an infinite loop in lit_i_read_secondary_header() in lib/litheaders.c. The block walk advances with "offset += blocklen" where blocklen is read via the READ_INT32 macro, which masks the sign bit (& 0x7FFFFFFF). The guard "if (blocklen < 0) break;" is therefore unreachable dead code, and a block length of 0 combined with a block tag that matches neither CAOL nor ITSF (the switch has no default case) leaves offset unchanged, so the loop never terminates. Opening a crafted .lit file of 133 bytes with the clit utility causes it to consume 100% of one CPU core indefinitely. The supplier has been unmaintained since 2003 and could not be contacted.

## Proof of concept

```
sec_infloop_min.lit (container, 133 B), m_0_16.lit, c1.lit
```

## Verification

hang; process pinned at ~100% CPU of one core (state R, stime 0, wchan 0)

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open or convert untrusted .lit files with ConvertLIT. Distributions may consider dropping the package, as upstream has been unmaintained since 2003.

## Solution

No fixed version is available. The upstream project has received no update since 2003 and has no contactable maintainer.
