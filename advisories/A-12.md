## Description

CHMLib 0.40 reads out of bounds in _chm_skip_cword() and _chm_parse_cword() in src/chm_lib.c. ENCINT values are decoded without validating the remaining input length, so a crafted .chm file causes a read past the end of the directory page buffer. Note for triage: CVE-2005-2930 concerned a different defect in the same function and was fixed in 0.36/0.37; this report targets the final release 0.40 and is offered as an incomplete-fix claim. The supplier's last commit is 2009-07-02; 0.40 is the final release and the supplier could not be contacted.

## Proof of concept

```
a_encint.chm
```

## Verification

ASan heap-buffer-overflow at src/chm_lib.c:1109

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open untrusted .chm files with applications linking CHMLib. Upstream's last commit is 2009-07-02 and there has been no release since.

## Solution

No fixed version is available. 0.40 is the final release and upstream is unmaintained.
