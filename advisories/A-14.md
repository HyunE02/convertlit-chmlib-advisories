## Description

CHMLib 0.40 reads out of bounds in src/chm_lib.c because the ITSP header field block_len is used directly as the directory page buffer size with no minimum validation. The buffer is allocated with malloc(block_len) and then read with a fixed-size access, so a small declared block_len causes a heap out-of-bounds read. Note for triage: CVE-2007-0619 concerned a crafted page block length and was fixed before 0.39; this report targets the final release 0.40 and is offered as an incomplete-fix claim. The supplier's last commit is 2009-07-02; 0.40 is the final release and the supplier could not be contacted.

## Proof of concept

```
e_blocklen1.chm, e_blocklen4.chm, e_blocklen19.chm, e_blocklen20.chm
```

## Verification

ASan heap-buffer-overflow at src/chm_lib.c:260, :272, :1280; one variant hangs

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open untrusted .chm files with applications linking CHMLib. Upstream's last commit is 2009-07-02 and there has been no release since.

## Solution

No fixed version is available. 0.40 is the final release and upstream is unmaintained.
