| | |
|---|---|

## Description

ConvertLIT (clit18) 1.8 passes a negative length to strncpy() in lit_read_atoms() in lib/litatom.c. In the attribute-map string loop the length is read with "len = READ_U32(p)" into an int, so a field value of 0xFFFFFFFF yields -1. The bounds check "if (len > nbytes) break;" is a signed comparison and -1 passes it, malloc(len + 1) becomes malloc(0) and succeeds, and strncpy(s, p, len) then receives (size_t)-1 as its size while "s[len] = 0" writes before the allocation. The supplier has been unmaintained since 2003 and could not be contacted.

## Proof of concept

```
f13.lit (container), attr_signed_len_write.bin
```

## Verification

ASan negative-size-param (size=-1) in strncpy from lib/litatom.c:186

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open or convert untrusted .lit files with ConvertLIT. Distributions may consider dropping the package, as upstream has been unmaintained since 2003.

## Solution

No fixed version is available. The upstream project has received no update since 2003 and has no contactable maintainer.
