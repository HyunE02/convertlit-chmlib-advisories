# A-10 — CWE-125 Out-of-bounds Read

| | |
|---|---|
| **Product** | ConvertLIT project — ConvertLIT (clit18) |
| **Affected version** | 1.8 (final release; other versions untested) |
| **Weakness** | CWE-125 |
| **CVSS 4.0** | `CVSS:4.0/AV:L/AC:L/AT:N/PR:N/UI:A/VC:N/VI:N/VA:H/SC:N/SI:N/SA:N` (6.7 MEDIUM) |
| **Source file** | `lib/litutil.c` |
| **Routine** | `lit_i_utf8_len_to_bytes` |
| **CVE ID** | requested from MITRE CNA-LR on 2026-11-24 — pending |

## Description

ConvertLIT (clit18) 1.8 reads out of bounds in lit_i_utf8_len_to_bytes() in lib/litutil.c. Both of its loops dereference src[nbytes] before validating nbytes against sizeSrc. The caller lit_i_read_utf8_string() passes src = p + 1 and sizeSrc = (pEnd - p) - 1, so src + sizeSrc is exactly pEnd and src[sizeSrc] reads one byte past the end of the manifest buffer. Setting a string length byte equal to the number of remaining bytes makes the first loop exit with nbytes == sizeSrc and the second loop read out of bounds immediately. Reached from the public API lit_read_manifest(). The supplier has been unmaintained since 2003 and could not be contacted.

## Proof of concept

```
f15.lit (container), manifest_utf8_overread.bin
```

## Verification

ASan heap-buffer-overflow READ at lib/litutil.c:132, 0 bytes after a 19-byte region

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open or convert untrusted .lit files with ConvertLIT. Distributions may consider dropping the package, as upstream has been unmaintained since 2003.

## Solution

No fixed version is available. The upstream project has received no update since 2003 and has no contactable maintainer.
