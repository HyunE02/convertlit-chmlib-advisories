# A-09 — CWE-476 NULL Pointer Dereference

| | |
|---|---|
| **Product** | ConvertLIT project — ConvertLIT (clit18) |
| **Affected version** | 1.8 (final release; other versions untested) |
| **Weakness** | CWE-476 |
| **CVSS 4.0** | `CVSS:4.0/AV:L/AC:L/AT:N/PR:N/UI:A/VC:N/VI:N/VA:H/SC:N/SI:N/SA:N` (6.7 MEDIUM) |
| **Source file** | `lib/litsections.c` |
| **Routine** | `decompress_section` |
| **CVE ID** | requested from MITRE CNA-LR on 2026-11-24 — pending |

## Description

ConvertLIT (clit18) 1.8 dereferences a malloc() result before checking it for NULL in decompress_section() in lib/litsections.c. The sequence is "ptr = malloc(uclength+1); ptr[uclength] = 0xCC; if (!ptr) { ... }", so the corruption-sentinel store executes unconditionally. uclength is read with READ_INT32, which masks the sign bit and therefore yields a value in [0, INT_MAX]; at INT_MAX the expression uclength + 1 overflows to INT_MIN and is sign-extended to 0xFFFFFFFF80000000 as the size_t argument, so the allocation fails and the store targets address uclength. On memory-constrained systems much smaller values also fail allocation, giving the attacker a range of write offsets. The supplier has been unmaintained since 2003 and could not be contacted.

## Proof of concept

```
f14.lit (container), sect_uclen_intmax.bin
```

## Verification

SIGSEGV at lib/litsections.c:369 (build at -O0; see note)

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open or convert untrusted .lit files with ConvertLIT. Distributions may consider dropping the package, as upstream has been unmaintained since 2003.

## Solution

No fixed version is available. The upstream project has received no update since 2003 and has no contactable maintainer.
