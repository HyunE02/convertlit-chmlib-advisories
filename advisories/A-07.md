# A-07 — CWE-190 Integer Overflow or Wraparound

| | |
|---|---|
| **Product** | ConvertLIT project — ConvertLIT (clit18) |
| **Affected version** | 1.8 (final release; other versions untested) |
| **Weakness** | CWE-190 |
| **CVSS 4.0** | `CVSS:4.0/AV:L/AC:L/AT:N/PR:N/UI:A/VC:N/VI:L/VA:H/SC:N/SI:N/SA:N` (6.8 MEDIUM) |
| **Source file** | `lib/litatom.c` |
| **Routine** | `lit_read_atoms` |
| **CVE ID** | requested from MITRE CNA-LR on 2026-11-24 — pending |

## Description

ConvertLIT (clit18) 1.8 writes out of bounds in lit_read_atoms() in lib/litatom.c. The allocation size is computed as "len = nEntries * sizeof(char *) + sizeof(lit_atom_list)" where nEntries is an unchecked 32-bit value from the file and both nEntries and len are of type int. The product is evaluated in 64-bit but truncated when stored into the int, while list->num_atoms and the loop bound keep the untruncated value. On x86-64, nEntries = 0x1FFFFFFC truncates a required 4 GiB to zero, so malloc(0) is followed by writes of heap pointers into list->atom_names[]. The attribute-map path has the same defect at "len = sizeof(lit_attr_map) * (nEntries + 1)". The extent of the overflow is bounded only by the input length. The supplier has been unmaintained since 2003 and could not be contacted.

## Proof of concept

```
f12a.lit, f12b.lit, f12c.lit (containers), atom_trunc_*.bin
```

## Verification

ASan heap-buffer-overflow WRITE at lib/litatom.c:99, :126 and :189

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open or convert untrusted .lit files with ConvertLIT. Distributions may consider dropping the package, as upstream has been unmaintained since 2003.

## Solution

No fixed version is available. The upstream project has received no update since 2003 and has no contactable maintainer.
