# A-02 — CWE-125 Out-of-bounds Read

| | |
|---|---|
| **Product** | ConvertLIT project — ConvertLIT (clit18) |
| **Affected version** | 1.8 (final release; other versions untested) |
| **Weakness** | CWE-125 |
| **CVSS 4.0** | `CVSS:4.0/AV:L/AC:L/AT:N/PR:N/UI:A/VC:N/VI:N/VA:H/SC:N/SI:N/SA:N` (6.7 MEDIUM) |
| **Source file** | `lib/litheaders.c` |
| **Routine** | `lit_i_read_secondary_header` |
| **CVE ID** | requested from MITRE CNA-LR on 2026-11-24 — pending |

## Description

ConvertLIT (clit18) 1.8 reads out of bounds in lit_i_read_secondary_header() in lib/litheaders.c. The loop condition tests only "offset < len" while each iteration reads a 12-byte block header (tag at +0, version at +4, length at +8) through the unchecked READ_U32/READ_INT32 macros, so an offset within 11 bytes of the end reads past the allocation. The initial offset is itself taken from the file with no bound check. Opening a crafted .lit file causes a heap out-of-bounds read. The supplier has been unmaintained since 2003 and could not be contacted.

## Proof of concept

```
sec_oob_np5.lit (container, 248 B), m_0_8.lit, c0.lit
```

## Verification

ASan heap-buffer-overflow at lib/litheaders.c:633-634

Every proof of concept was executed **five times in independent runs** with a freshly
created working directory. All runs produced an identical signature and crash location;
no flaky or environment-dependent results were observed. See
[`../VERIFICATION.md`](../VERIFICATION.md).

## Workaround

Do not open or convert untrusted .lit files with ConvertLIT. Distributions may consider dropping the package, as upstream has been unmaintained since 2003.

## Solution

No fixed version is available. The upstream project has received no update since 2003 and has no contactable maintainer.
